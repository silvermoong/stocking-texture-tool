# 丝袜纹理工具：功能全解

写 README、宣传视频脚本、效果展示时，以这份文件为准：功能、界面名称、数字、哪些说法准确都在这里。每节末尾标了代码位置，要更细的行为去那里核实。界面上的全部文字（中英对照）在 `stocking/static/i18n/en.json`：键是中文，值是英文。

状态：里程碑 1–5 已完成，里程碑 6「开源准备」进行中（2026-10-07，提交 cfe73ca，测试 136 项全过）。

## 一句话

一个本地桌面工具：给插画里的丝袜加上真实、没有摩尔纹的织物纹理。用户粗涂出丝袜所在的部位，沿横纹方向画几条线，工具就算出纹理怎样绕着腿和身体走，按选定的样式渲染。可以导出成品图、可以叠在原图上的「仅丝袜」透明 PNG，以及能再打开接着改的引导 PSD。全程在本机运行，不上传任何东西。纹理是算出来的，不是生成式 AI 画的；AI 只用在两处：点选抠部位（SAM），以及估算画面深度（Depth Anything V2）。

## 主流程

这也是视频的主线，五步：

1. **打开图**：拖进窗口，或 Ctrl+O。
2. **引导页第 1 步「部位」**：用点选一下选出一条腿，画笔和橡皮修边，需要时切开（比如两胸分开）。默认已经有「左腿」「右腿」两个部位。
3. **引导页第 2 步「走向」**：每个部位沿横纹画 1–3 条线，1–2 秒后横纹铺满这个部位。另一侧点「镜像」直接翻过去。腿弯折、大腿压着小腿的交界，用「隔开（W）」画一条线，膝盖再加一条弧线过渡；一块丝袜挡在另一块前面、有深度落差的地方，深度模型会尽量自动找出隔开线。
4. **纹理页**：选样式，拖密度、强度、亮点；想要摩尔纹就打开摩尔纹效果的开关，再调强度、面积。「细节」方块随滑杆实时变化，「整体」显示全图，可以拖分界线对比原图。「标出问题」检查哪里没纹理。
5. **导出**：成品图、仅丝袜 PNG 或丝袜引导.psd，一次导出一种。

## 打开、保存、撤销

- **能打开：** PNG、JPG、WEBP、BMP、TIFF、PSD/PSB。三种方式：拖进窗口；拖到 `start.bat` 或桌面快捷方式上；Ctrl+O 或「打开…」。
- **PSD：** 取合成图。「丝袜引导」组，以及名字含「丝袜纹理」的图层，不算原图。
  - 带「丝袜引导」组的 PSD 会把部位、走向线、亮点层、隔开线一起读进来。这个组可以是工具导出的，也可以在 Photoshop 里照同样格式手画。组名中英文都认。
  - 组的格式：每个部位一个图层（图层名就是部位名），另有「走向」「亮点」「隔开」三层。
- **原文件不动：** 用户自己的 PSD 永远不会被写入。用户的 PSD 里常有智能对象和生成式填充图层，用 Python 改写有损坏风险。
- **自动保存：** 每次编辑都存到 `%LOCALAPPDATA%\StockingTexture\session`，关掉或崩溃后重开，从上次的地方继续。撤销历史不保存。
- **换图提醒：** 当前图的部位和走向线还没导出时打开新图，会弹窗提供三个选项：先导出丝袜引导.psd / 直接打开 / 取消。
- **撤销 / 重做：** Ctrl+Z / Ctrl+Shift+Z（或 Ctrl+Y），最多 200 步。涂抹、点选、走向线、隔开、合并、分割、镜像、颜色排除，每个操作撤销一次就回去。最近的求解结果有缓存，撤销后横纹立刻回来，不用重算。

代码：`stocking/document.py`、`session.py`、`psd_io.py`、`server.py`

## 部位（引导页第 1 步）

**部位列表**
- 默认有「左腿」「右腿」（英文界面是 Left leg / Right leg）。
- 「+」添加一个部位，添加后直接进入改名；F2 或双击也能改名。
- 每行右侧的「···」菜单：改名、清空、合并到（子菜单里挨着的部位排在前面，标「相邻」）、删除。每个操作都能撤销。
- 每行显示当前状态：还没涂 / 还没画走向线 / 等待求解… / 正在求解… / N 条走向线，求解 X 秒 / 有一块分开的没画走向线。

**工具**（快捷键）
- **点选 S**（SAM）：左键把点到的那块加进当前部位，右键从当前部位减去。
  - 点完旁边会出现「小 / 中 / 大」三档范围，Tab 循环切换。
  - 默认是最小档，因为大档容易把头发、另一条腿、鞋子也选进来。
  - 4090 上每次点击约 30 毫秒。
- **画笔 B**：涂当前部位，右键擦除。画笔会从别的部位里抢像素。笔刷 2–400 px，`[` `]` 调大小。
- **橡皮 E**：擦当前部位。
- **切开 K**：在当前部位上画一条线，松开鼠标就分成两块。
  - 线不用画满，两端会顺着方向自动延长（画面上显示为虚线）。
  - 「自动贴线」开着时，手抖的线会吸到附近的线稿上，比如乳沟的折线。
  - 「自动分割」按钮不用画线，专门用来分开选在一块里的左右一对（两胸、两条腿、一件上衣的左右两半）：先找这块选区的镜像对称轴（翻过去重合得最好的那条线），沿它切，附近有画出来的暗线或缝隙就顺着走。选区是横长、竖长还是方形都不影响。不是左右一对的（比如侧面看的近侧腿和远侧腿），自己画线切。
  - 分出来的两块叫「原名-左/-右」或「-上/-下」。Esc 回到原来的工具。

**显示**
- 部位以彩色半透明覆盖显示，共 10 种颜色。
- 「覆盖范围」开关：变暗的地方是颜色排除掉的部分，同时显示「部位里 N% 会出纹理」。

**怎么分部位**
- 凡是有折痕的地方，两边各一个部位：左右大腿、胯部、左右胸。如果一个部位跨过折痕，两边的横纹会互相折进去。
- 例外是一条弯折的腿：它可以是一个部位，膝盖处的遮挡由隔开线处理，见下文。

代码：`document.py`（部位、合并、分割）、`sam.py`、`split.py`、`coverage.py`、`static/app.js`

## 走向线和横纹（引导页第 2 步）

这是工具的核心：用户画几条线，工具把横纹铺满整个部位。

**怎么画**（可以直接用作视频教学旁白）
- **沿一道横纹画：** 横纹是绕腿一圈一圈的线，所以在腿上画的是横穿过腿的弧线，像画腿上套着的环可以看见的那半圈。弧往哪边弯，决定了腿是从上往下看还是从下往上看。
- **数量：** 每个部位 1–3 条就够，每条横跨部位宽度的大约八成。
- **线只管方向，不管疏密：** 画得密还是稀，横纹间距都一样，间距由纹理页的密度决定。用户不用担心线画得不均匀。
- **方向变化大的地方各补一条：** 比如膝盖上下各一条。
- **可以穿过遮挡：** 线可以横穿手或头发，横纹会在遮挡物下面继续。
- **删除和刷新：** 右键或 Delete 删掉指针下的线（指针移上去线会高亮）。每画一条，只重算这一个部位，约 1–2 秒，状态栏会显示「左腿的横纹已更新，用时 X 秒」。
- **胸：** 先用切开沿乳沟分成左右两个部位，再顺着胸的弧度画。
- **显示开关：** 走向线、横纹、纵纹、隔开线。

**原理**（给 README 的「工作原理」和视频的讲解段）
- 方向：把各条线的方向在整个部位内平滑插值出一个方向场。一条腿弯过来时，横纹的朝向会顺着腿传播，绕过弯处不会翻转。
- 坐标：解一个最小二乘问题，得到一个坐标 V，各处的梯度都等于 1。横纹就是 V 的等值线，在屏幕上处处等距。
- 纵纹：取「沿横纹的弧长」，零点在部位的中线上。
- 求解只在每个部位自己的包围框里、1/4 分辨率下进行，所以快。

**遮挡处理**（视频里很好演示）
- **手、头发盖在腿上：** 部位里的洞，以及比腿宽一半还窄的缺口，求解时当作被填满。横纹在遮挡物下面连续走，手两侧的横纹是对齐的，不会绕着手弯。
- **一条腿被另一条腿挡成两截：** 后面那截会自动接上前面那截的横纹，像腿在后面继续一样。接不上时，部位状态会提示「有一块分开的没画走向线」，在那截上补一条线即可。

代码：`guide_fields.py`（`solve_v`、`solve_across`、`fill_occlusions`、`bridge_pieces`）、`document.py`

## 隔开线：弯折的腿、交叠的腿

**问题：** 一条腿弯到小腿折在大腿后面时，大腿和小腿的横纹不该连在一起。早期版本只能把腿切成两个部位，膝盖处会留下一道接缝。

**自动隔开**
- 打开图片后深度模型就在后台算深度，GPU 上约 0.1 秒。
- 工具在深度图里找又陡、又尖、落差又大的台阶，并且台阶两侧都要是丝袜。这就是一块丝袜挡在另一块前面的轮廓。
- 以下几种不会被当成隔开：腿的外轮廓（另一侧是背景）；手或头发的边（另一侧是遮挡物）；丝袜上画出来的花纹或褶皱（没有深度台阶）。
- 找到的隔开线用虚线显示。横纹不会穿过它，而是从线的两端绕过去。所以一条弯折的腿可以只用一个部位，膝盖处没有接缝。

**手动隔开 W**
- 沿两块丝袜的交界画线即可，用户画的显示为实线。
- 右键或 Delete 删掉指针下的隔开线，自动找到的也能删，删除会被记住。

**自动找不到的：两块丝袜贴在一起**
- 自动隔开只认遮挡（一块在另一块前面，中间有深度台阶）。大腿压在小腿上（跪坐、蹲姿）、两胸之间的乳沟，是两块丝袜贴在一起，深度上没有台阶，要用 W 手画。素材 B2 就是这种情况，Small 和 Large 两个深度模型都找不到。
- 不做自动检测的原因：贴在一起的交界（横纹要断开）和身体本身的凹处（比如胸和胸骨之间，布料是连续的，横纹要连着走），在可见的深度和画面上可以完全一样，区别在看不见的布料怎么连。试过折痕检测，会在手指边、乳沟内侧误判，所以没有上线。
- 隔开工具的悬停说明写了这一点（第 2 步不再放常驻提示）。

代码：`walls.py`、`guide_fields.py`（`Grid` 的 cut、`orient`）、`depth.py`

## 镜像

- **怎么用：** 选中一侧的部位，点第 2 步工具行最右边的「镜像」。悬停提示会写出镜像到哪个部位。
- **自动配对：** 名字里左右互换就是对侧（左腿↔右腿，左胸-左↔右胸-右，英文 left/right 也认）。没有对侧的部位（比如胯部），按钮会弹出列表让用户选目标。
- **原理：** 用一个带翻转的相似变换（翻转、旋转、缩放、平移）把这一侧的轮廓对齐到另一侧，再把走向线搬过去，裁剪到目标部位里。搬过去的线会替换目标原来的走向线。
- **结果：** 镜像出来的线是普通走向线，可以照常修改或删除。真实姿势往往不对称，镜像只是起点。整个操作撤销一次就回去。
- **准确度：** 在甘雨测试图上，镜像后的横纹和手画的相比，大腿中位偏差 1.7°，胸 8.2°；两边看起来都合理。

代码：`symmetry.py`、`document.py` 的 `mirror_strokes`

## 为什么看起来贴合身体

视频里讲「贴合凸起凹陷」时，按下面这些机制讲。每一条都是实际起作用的。

1. **横纹走向跟着身体：** 横纹的弯曲来自用户画的弧线，腿上一圈圈的弧本身就表达了圆柱的体积和视角。
2. **纹理乘在原画上：** 纹理是原画乘以一个比例，所以完整继承原画的明暗。亮处纹理亮，暗处纹理暗，画师画的高光和阴影全部保留。最暗的地方纹理自动淡出，阴影保持干净。
3. **缝隙颜色按每个部位整体的深浅决定（细线、针织、线圈）：** 纱线之间的缝隙取决于这个部位的丝袜整体是深还是浅：取部位内丝袜像素周围约 25 px 范围亮度的中位数，和一个分界值比（细线、针织 0.55，线圈 0.675）。深的部位缝隙变亮成暖色亮线，浅的部位缝隙变暗成粉色细线，二选一，不渐变。一条腿黑丝一条腿白丝，各用各的；黑丝膝盖上一块很亮的高光，仍然是黑丝的暖色亮线。限制：一个部位里混着两种材质（黑丝带一圈浅色蕾丝顶带）时，整个部位只用一种。以前是逐像素按局部明暗判断，在亮度正好穿过分界值的地方两种画法互相抵消，高光周围会出现一圈没有纹理的带，整件落在分界值附近的丝袜（中灰、晒黑色）纹理也几乎消失。
4. **亮点落在鼓起的地方：** 「按深度」的亮点放在比周围更凸出的地方（膝盖顶、大腿正面、胸顶），并偏向受光的一侧。「按画面亮部」的亮点放在画师画的高光上。
5. **遮挡和折叠：** 手和头发下面的横纹连续，弯折和交叠处有隔开线，纹理的结构和画面里的前后关系一致。
6. **油光样式（试验）把体积感做得最强：** 把每段肢体当成旋转体。正对观众的地方透出肤色，越往轮廓边缘丝袜越密越暗，深色丝袜的边缘直接变黑（照真实油光黑丝的商品图量出来：离中线 0.8 个半宽处是中间亮度的 0.76，0.9 处是 0.54），这就是真实丝袜的厚度效果。受光一侧整片泛光。最亮处是一条连续的反光带：细而亮的芯，外面一整片宽而柔的光，宽度随腿的粗细走（大腿宽、小腿窄），形状照着真实油光黑丝的商品图量出来；沿腿走多远取决于画师画的高光有多长，走远了是渐渐变淡，不会断成一截一截。

**不要宣传：「横纹间距随凸起变疏、随凹陷变密」**
- 工具没有这个功能。曾经做过一个「起伏松紧」（按深度让横纹变疏变密），用户试过后决定删掉。
- 走向线的疏密也不影响横纹间距，横纹在屏幕上是等距的。
- 体积感来自上面 1–6 条。

## 纹理页：样式

| 样式 | 代码键 | English | 样子 | 适合 |
| --- | --- | --- | --- | --- |
| 细线（默认） | `knit` | Fine lines | 宽纱线之间一道细缝透出肤色：浅色丝袜上是粉色细线，深色丝袜上是暖色亮线。照着一张白色针织丝袜的画做的 | 大多数丝袜，白丝黑丝都行 |
| 针织 | `loops` | Knit | 一列列 V 形线圈，像丝袜脚底加厚部分的织法。线圈小，密度调低一些更清楚 | 想看到明显织纹 |
| 斜单线 | `lines` | Slanted lines | 斜着走的单线，加暖色单像素闪光。斜度 0–60°（默认 32°），两条腿方向相反，左右对称成人字形 | 有光泽的薄丝 |
| 加濑风 | `grain` | Kase | 细碎的 1–2 px 颗粒（暗部更重，带一点彩色）叠在很淡的针织上，加白色小亮点 | 颗粒感、哑光 |
| 油光（试验） | `oily` | Glossy (Beta) | 半透明油亮丝袜，正对处透肤、深色丝袜边缘发黑、亮侧泛光、一条宽而柔的连续反光带，见上节第 6 条 | 有明显高光的纯色黑丝；换一张图效果可能不稳定 |

- 每种样式都能加亮点：斜单线是暖色单像素闪光，其他样式是白色小亮点。
- 斜单线怎么分左右：名字里带「左/右」（或 left/right）的部位按名字决定倾斜方向；其他部位按在画面左半还是右半；横跨中间的（比如胯部）不斜。
- 油光的反光自动沿着腿看上去的中间走（没有设置，也不是写死在正中）：真实的油光丝袜，反光多半落在腿看上去的中间一带、两边偏暗（物理上，反光在法线正对「光与镜头的中间方向」处，光偏离镜头 φ 角时离中线 sin(φ/2) 个半宽：60° 是 0.5，90° 是 0.71；侧光、逆光、腿转向一侧或被遮挡时才会靠边，见 `.scratch/oily-glint-centre/research.md`）。画面里的光在一片平顶上只有几级灰度的小起伏（笔触的偶然）时，最高的那一点会在中间的小台阶和旁边稍高的小鼓包之间来回跳，反光就跟着走歪、断开；现在在「和最高点几乎一样高」的各处（局部高点，上下差在 `LEVEL`=0.05 亮度以内，中间的凹谷不深于 `RIDGE`=0.025——再深，较低的那一边自己也够得上一条反光，就是两条脊而不是同一个顶）里，选最靠中间的，整条反光沿一条连续的路径走（每行最多走一条反光能走的那么快，不会折）。明显更高的鼓包（超过 `LEVEL`）、已经在中间附近（`CENTRAL`=0.35 个半宽以内）的反光、画在边上而旁边没有同高之处的反光，都照画面的来，不会丢掉任何反光，也不会冒出原来没有的；挪过去的反光亮度不变；反光中途被遮挡、「走到了看不见的地方」的那一条（`oily.py` 里叫 went on unseen）整条不动，和它共用任何一行的别的反光也不动（它被带着走的那条线画在哪里并不确定）。「中间」是画面上看到的腿的中线 c(V)（两侧轮廓的中点，随腿的弯曲而弯，用的是横纹的横向坐标 A，纵纹顺着它走），不是腿真实的中轴；整个部位都看不到一圈完整轮廓（比如腿被画面边缘截断）时中线只是猜的，不挪。做法见 `oily.py` 的 `_centre`（逐条反光做一次动态规划）。
- 油光反光的形状照真实油光黑丝的商品图（Temu、淘宝等，用户在 Google 图片里搜的「油丝 黑丝 / 白丝」）量出来：反光是从大腿到脚踝一整条连续的宽而柔的光带，反差沿腿渐渐变小（大腿约 100 级灰度，小腿 30–50，脚踝约 10），不是一根线。横截面（离峰的距离按腿的半宽算）：0 → 1.00，0.1 → 0.58，0.2 → 0.37，0.3 → 0.28，0.5 → 0.18，0.8 → 0.08；旧的细线模型只有 1.00、0.25、0.12、0.08。照这条曲线拟合成「窄芯 + 宽带 + 指数尾」三层（σ 分别是 0.064、0.54 个半宽，尾长 0.20 个半宽，权重 0.31/0.20/0.39，合起来仍是 0.90，所以满强度的最亮处没变），宽度跟着腿的半宽走（`CORE_REL`、`BAND_REL`、`TAIL_REL`），画师画的高光宽就更宽（×0.8–1.6）。三处顺带改了：纹理对反光两侧的削弱从 0.55 降到 0.15 / 0.25（以前细线的两侧几乎全算「侧翼」，被横纹切成一段一段，这是用户看到「线是断的」的主要原因之一）；反光随画面光变强弱的指数 `SPEC_EXP` 从 6 降到 3（6 次方会把画师笔触上 ±10% 的起伏放大成 ±50% 的强弱，沿线忽明忽暗）；反光路径允许离画出的峰偏 `TOL_REL`=0.07 个半宽（画师笔触的抖动不是真反光的抖动）。PSD 左小腿在强度 35 / 60 / 100 / 150 下放大看：旧的是一条时断时续的细线，新的在每一档都是连续的光带（强度只改亮度，不改连续性）。还没做的：画里没有高光的地方（比如 PSD 膝盖一段，原画那里没画高光，大腿小腿又是分开的两块）反光仍然是断开的，真实照片里是跨过膝盖连着的。
- 油光的分区（深色丝袜）：边缘按「丝袜沿视线方向的厚度是 1/正对程度」变黑，系数 `KAPPA`=0.35，中间按 `K_SEE`=0.08 透出一点暖色肤色；只对深色丝袜（这个部位丝袜亮度中位数低于 0.30 全开，高于 0.75 全关，`DARK`）、轮廓看得见的地方（整圈轮廓看得见 1，一侧被挡 0.5，两侧被挡或整段都没看全 0）和够宽的腿（半宽 8 px 以上全开，4 px 以下不加）生效。所以白丝几乎不变（两张白丝图差 0.00 级灰度，PSD 平均差 0.36），被裙摆、画面边缘、另一条腿挡着的轮廓不会硬加黑边，一根线细的肢体不加。用走向线找高光线的试验没有采用（见研究笔记：一条直线盖不住会晃的高光，会在没有高光的地方凭空连线，也会吃掉第二个光源），找光仍然是现在的追踪器。还没做的：高光所在的一侧边缘不变黑（照片里那一侧反而比中间亮）。
- 油光的底线光（`FLOOR_GLINT`，原来的"默认中线"改成了这个）：真实油光黑丝的反光是沿着整条腿的，由强渐弱但不会没有（商品图上大腿约 100 灰阶、小腿 30–50、脚踝约 10）。所以深色丝袜、轮廓看得全、肢体够宽的一段，从头到尾都有一道 0.4 强度（画出的高光最强是 1）的光，按分区的可信度逐行乘（轮廓被挡的地方变淡，白丝上没有）。它和画出的主高光（光最多的那条）是**同一条路径**，不是旁边多一条：画得比它强的地方就是画出来的样子（位置、强度逐位不变）；画暗了就把强度抬到底线，位置从画出的位置过渡到这条高光"看得清的行"的位置（强度不小于最强处一半、画里确定看见的、在肢体以内），在它的两头和空白处保持这个位置（一盏光照一条直的肢体，位置不变）；整条腿都没画高光就走腿看上去的中线。只补「像肢体的一段」（长度至少是腿宽的 1.5 倍，脚、圆鼓鼓的臀和膝盖不补；被丝带、手、头发隔开的几段算一条肢体的长度）。画出的高光弱到 0.075 以下当没有，到 0.15 渐渐跟随，不会因为画师多画了一点点就一下子挪位置。**修的是**：黑色油丝的小腿没有光——大腿画了高光、小腿没画（或画得太弱被判成"不够亮"丢掉）的整只腿，原来只有"整段都没画高光"才补，现在整条腿都有。在 15 张真实图上，黑丝都有变化（小腿从膝盖到脚踝一条连续的细线；12347558、12299022、b1black 最明显），白丝一个像素都没变（0.00）。已知限制：整条线强度是平的，没有向脚踝渐弱；样例图（6b6a4476）的臀部那一块被当成"够长的一段"，热点下面会拖出一条细线；两盏光强度几乎一样时，底线跟哪一盏取决于谁更强一点（并列时两条画出的高光都照旧，只是底线接在其中一条上）。
- 被遮挡隔开的肢体（`Document.filled_map`、`oily._pieces`、`oily._joins`）：脚和腿是同一个选区、中间被丝带、鞋带或头发挡住时，求解器其实把中间补上了（`fill_occlusions`），但油光原来只看选区本身，把它们当两块，脚太短就没有光。现在补出来的缝隙做两件事。**一，判断哪几块是同一条肢体**：一块在另一块的前面或后面沿肢体方向排开（V 范围重叠少于 0.75、A 范围重叠至少 0.5，且都大于 64 px；斜到约 55° 以内的带都算），并排的两条腿、顺着腿的发丝都不算。同一条肢体里，长度按全部几块算；没有自己高光的一块接上其他块的高光：前后两边各按距离从近到远，越清楚越算数（弱得只露个影子的只给个提示，其余听更远那块清楚的），前后两边都有就从一头渐变到另一头，两道缝处都对得上（渐变按这一块实际的第一行像素到最后一行算，不是按光照拟合的行：拟合的最后一行常常只有一部分在片里）；自己高光很弱的一块也照样接着这个位置，不会一弱就回到腿中间；离得一样近（按一个像素算，不是比求解器的最后几位数）、一样大的两块不偏向哪一边，取平均（清楚的那块说了算得多）；窄到只有光照拟合一行、而且片里的像素不超过两个拟合行高的细条（几十个像素以内）不画一个点，按它长度的三等分画一条贯穿的线，从上端的位置到下端的位置，每一等分取在它那些像素的均值处，画出的高光再弱也一样（弱到几乎看不出的一条画出的高光原来会让整条线变回一个点）。**每块画出的高光不动**（最大的教训：一开始我把几块并成一块去算，结果你的白丝 PSD 里脚更亮，把这一块的亮度范围撑宽，小腿的高光被判成"不够亮"整条消失了；并成一块还会让 `_local_linear` 在宽度突变处外推出离谱的斜率）。**二，缝隙那一侧的边不是肢体的轮廓**：丝带斜着切过腿，每一圈只露出一部分，原来把露出那部分的中点当成腿的中线，光线在丝带上下都被带偏（B1 右脚：丝带上面往右偏，下面从左边缘斜插回脚中间；合成腿上偏 36–75 px），现在这一侧按"被挡住"处理（和墙、别的部位一样），中线用另一侧的轮廓加上腿宽算，丝带上下的线笔直对上，丝带边上也不再被当成轮廓压暗。只对连着同一条肢体至少两块的那段缝隙这样处理：边缘的缺口（求解器顺手补上的）自己单独成一块时是肢体自己的轮廓，并排的两块也一样，都不动；缝隙把每一圈都挡住的短条照旧；切口处量出来的宽度不会比不算缝隙时看到的更窄（只剩脚尖那几行"完整的截面"时，整块的典型宽度会塌到几个像素，光照网格细到找不到高光，所以有个下限）；切口那一侧的框架要在某处至少相信轮廓到老框架最佳值的四分之一，否则按老办法量（5、6 px 的细条只有三个 V 带、只有中间一带完整，可信度被光滑成 0.02，底线光低于门槛，一条线都没有）。缝隙里的像素不画任何东西；遇到墙（分隔线）的那一圈不算缝隙。白丝 PSD（鞋带、蕾丝边）的光线图因此更顺，每条腿一条连续的线。已知限制：一根头发顺着整条腿把腿劈成并排两条时不会连（认不出是头发还是两条腿）；斜得超过 55° 的带不算；两道斜带夹着的窄条用老办法量中线；**紧挨着丝带的边缘缺口会和丝带的缝隙连成一片**，掩码里分不出它和"肢体继续在后面"的头发，就一起当被挡住（实测深 40 px 的缺口紧贴丝带：缺口边的 facing 从 0.11 变成 0.86，那里的光线最多偏 20 px，往上影响约 90 px），没有为此再加判断。

- 光不穿过隔开线（`oily._closed_cut`、`oily._outside`，`oily_maps` 的两遍）：弯腿（蹲姿）上大腿压着小腿，用户画的隔开线常常只画到"看得见的地方"，在膝盖那头没有碰到轮廓，求解器照设计让横纹绕过线的这一端（见隔开线一节），所以大腿和小腿还是连在一起的一块。油光原来把这一块当成一条肢体：它的"正中间"是大腿＋隔开线＋小腿三者合起来的中间，也就是落在隔开线上；每一行里"在光的 A 位置的像素"取平均，大腿和小腿各有一处时平均出来就在线上——光顺着线走了一段，又上到大腿，穿过了隔开线；小腿自己画的高光也被大腿同 A 的像素摊薄了。现在：把每条隔开线的自由端沿最后一段的方向直着延长到部位的轮廓、另一条隔开线或已经延长的线（最远两倍部位半宽；碎片、短于 `walls.MIN_LEN` 或不到自身厚度 4 倍的不延长；找不到就不画），两侧各算一块，各有自己的光照拟合、高光和底线光；**外观（轮廓变黑的分区、正对程度、明暗）仍按没延长的线算**，单独一遍，所以和之前逐像素一样（16 张真实图 0.000），第二遍只写高光；这一遍里隔开线不当轮廓（不知道它背后腿有多宽），每侧的中间是看到的那部分的中间；光的路径若会进入另一块就在那里截断。在用户的蹲姿图上：光不再穿线，大腿的光从膝盖走到最亮处再沿大腿右缘下去，小腿自己有一条光到鞋；分区没有条纹或斜接缝。已知限制：线延长是直线、用最后 20～30 px 的方向，延长线若偏了，两块的交界也偏；隔开线两侧都挡着（一侧是另一个部位）的一段，底线光的强度借用没延长时的分区，不单独算。**隔开线没到头的那一端是开口的**（膝盖处纹理本来就绕过去）：延长出来的那段不是墙，一侧的光照亮另一侧紧挨着的丝袜，晕照常衰减，没有硬边（`_reach`：只要到光路的直线不穿过真正的隔开线，墙影做了模糊，边缘是半影不是锐边）。`oily.LIGHT_ACROSS_LINE=False` 关掉这件事。**不画任何东西去连接两侧的光**：两条光在膝盖处怎么走，由走向线和画出来的光自己决定（曾做过一条手工的弧把它们连起来，维护者认为这是为一张走向线本来就不完美的蹲姿打的补丁，去掉了）。用户的蹲姿图上：光不穿隔开线，延长线处没有硬边，小腿和大腿各有自己的光。限制：两侧的光在膝盖处是否连成一条，取决于走向场和画出来的高光，这个功能不保证。**用户确认这张蹲姿图（`b2-black-fold`）的走向线本身是不完美的**，其他图的结果是对的：别拿它当油光的基准，也别为它单独加补丁。

## 纹理页：密度、强度、颜色排除

**密度** 60–160%，默认 100%
- 100% 时，1280×1920 的图上每道横纹间距 4.6 px。间距随图片尺寸按面积的平方根缩放，所以同一张图放到同样的显示尺寸时，纹理观感一样。
- 滑杆下方显示当前间距，比如「横纹间距 4.60 px」。
- 间距最小 3.2 px，再密就会出摩尔纹。到下限时，界面会显示这张图最多能到多少 %，并建议先把图放大 1.5 倍再来。常见的 832×1216 出图就落在这个下限附近。

**强度** 0–200%，默认「自动」
- 同样的纹理在白丝上看起来大约是黑丝上的两倍强（在 L* 上实测）。所以「自动」会按丝袜的深浅给出建议值，范围 30–100%：黑丝 100%，白丝约一半。
- 拖动滑杆就改成手动，「改回自动」可以恢复。

**颜色排除**（默认开）
- 工具先算出部位里丝袜的颜色中心（Lab 色度的稳健中位数），偏离超过 6 个稳健标准差的像素不加纹理，比如金边、手套、头发、露出的皮肤。
- 薄丝袜透肤偏暖的地方（膝盖、脚尖）偶尔会被误排除，这时关掉开关，部位里每一处都加纹理。
- 这是文档设置：可以撤销，会随工作自动保存。

**全部恢复默认**：样式、密度、斜度、强度、亮点、摩尔纹效果全部回到默认值，按钮随即变成「撤销恢复默认」。

## 纹理页：预设

面板最上面：一个下拉（English: Presets）、「保存」「删除」两个按钮。

- **预设是什么：** 保存时纹理页上的全部设置（样式、密度、斜度、强度、亮点的各个来源和关联、摩尔纹效果），即 `look.clean_params` 的结果，所以以后新增的设置自动包含在内。强度是「自动」时只存这个标记，读取后按当前图的丝袜深浅重新算。颜色排除是文档设置，不在预设里；部位和走向线是每张图自己的。
- **存在哪：** 每个用户一份，`%LOCALAPPDATA%\StockingTexture\settings.json` 里的 `look_presets`，不是 localStorage（端口一变就丢）。不跟图走，也不进自动保存的工作。
- **读取：** 下拉里选一个就读取，替换现在的全部设置。读取之前的设置没有撤销记录，所以读取后出现「撤销载入」：连着读取几个，撤销回到第一次读取之前；之后动了任何设置，这个机会就没有了。
- **新建：** 下拉最下面一项「保存为新预设…」，选中弹出命名框（名字留空，写好才能点保存）。没选预设时点「保存」按钮也是这样。名字去掉首尾空格，1–40 个字，区分大小写；写了已有的名字，框里提示「会覆盖它」，没有第二次确认；覆盖时位置不变。
- **更新：** 选着一个预设时，「保存」按钮把现在的设置直接写进它，不弹窗，提示「已更新预设“…”」。设置和预设一样时这个按钮是灰的。
- **已改动：** 读取后动了设置，下拉下面写「已改动（和“…”不同）」，旁边的「还原」重新读取它。比较时忽略自动强度的数值，因为它随图片变。

- **读不了的预设：** 比如新版本存的、样式名这个版本不认识。下拉里标「（读不了）」，选中只提示、不改设置，可以删掉，也可以点「保存」用现在的设置覆盖修好它。读取列表不会改写文件，新版本存的预设不会被旧版本弄丢。

## 纹理页：摩尔纹效果（试验）

English: Moiré effect (Beta)。一个滑动开关（默认关），打开后下面才出现两个滑杆，都是 0–100%：**强度**（默认 100）和**面积**（默认 100）。给丝袜加上一圈圈水波似的明暗条纹，像现实里丝袜叠穿、拍照时出现的摩尔纹。

**开关和两个滑杆各管什么**
- 开关：滑动开关（实际是 `role="switch"` 的复选框，画成轨道加滑块；键盘 Tab 聚焦后按空格切换，点标题也能切换），在标题行最右边。默认关：两个滑杆收起，什么也不画，也不会去算深度。再打开时滑杆还停在原来的位置。开关状态是设置的一部分（`moire_on`），随图保存，也存进预设；旧预设没有这一项，读出来是关。「全部恢复默认」会把开关关上、滑杆回到 100。
- 强度：条纹的明暗有多深（丝袜亮度和纹理对比被条纹改动的量）。开着开关时拉到 0 也什么都不画。它和样式下面管整块纹理的「强度」是两个独立的滑杆，互不影响。
- 面积：每个鼓起处的条纹从顶上的一小块亮斑开始，一圈圈往外扩，环数跟着变多；拉满就是整个鼓起的地方都有，0 什么也不画。
- 位置、疏密、方向不让用户调：现实里摩尔纹的疏密、走向、弯曲由腿的形状和织物决定（两层细网周期或角度略有差，条纹宽度只取决于这个差；单层的织物和相机像素格打架，条纹也顺着曲面走），所以由工具按深度模型的鼓起算。
- 参数是试过多种方案后简化出来的：先是「间距、方向、随起伏」三个，条纹像一道道光带，不像摩尔纹；改成鼓起的等高线后才像；后来又加了「面积」，因为「每个部位固定 5 圈」不符合现实里「鼓得越高环越多」；最后因为把滑杆拉到 0 当「关」不直观，换成独立的开关。

**现实里是不是「一小圈→扩张→环数变多」（研究结论）**
- 是。两层细网叠在一起，条纹是两层之间「间隙」的等高线：影子摩尔纹 Δz = p/(tanα + tanβ)，条纹级数 N 与高度成正比（Rod Lakes《Shadow moire for experimental deformation analysis》）；牛顿环同理，第 N 个亮环半径 r_N = √(λR(N−½))，环数与半径平方成正比（Wikipedia「牛顿环」）。人体摩尔纹形貌术也是同一回事：条纹是身体曲面的等高线（Sensors 2026，PMC12900149）。
- 所以鼓起越高，第一圈先在顶上以一小圈出现，往外扩，再往顶上长出新的圈；抛物面形的鼓起每圈面积相等，圈内的环数和面积成正比。
- 严格说驱动它的是鼓起的高度（深度），不是单纯的大小：同样高的鼓起，宽一倍只是环变大，环数不变；真实身体上大的部位通常也鼓得更高，所以大部位环数更多。两层光栅叠加的仿真给出同样的结果：环数 ∝ 高度、与半径无关，各圈等面积，第一圈从顶上长出来。
- 没找到丝袜摩尔纹随拉伸变大的真实照片，依据是光学原理和仿真，不是对照实拍。

**现实里是不是只有一部分地方有（研究结论）**
- 是，现实里的摩尔纹也是局部的，原因有两层：
  - 两层图案叠在一起：Wikipedia「Moiré pattern」开头写明，两个图案「不能完全相同，必须有位移、旋转或间距略有差异」才出摩尔纹；两组平行线间距 p 和 p+δp 时，条纹间隔是 p²/δp + p，δp 越小间隔越大，趋于 0 时间隔无穷大，就是一整片均匀的明或暗，看不到条纹。所以两层贴得严、拉伸一样、方向一样的地方没有条纹；有条纹的是两层的间距、方向或间隙有差别的地方，在丝袜上就是拉伸不一样、起褶、叠层的地方。影子摩尔纹也一样：条纹是离光栅平面等深度的等高线，表面是平的就没有条纹，有凹凸才有（Rod Lakes《Shadow moire for experimental deformation analysis》）。
  - 拍照时织物和相机像素格打架：织物纱线的间距接近传感器像素时才出，曲面上织物的朝向和透视一直在变，只有一部分地方满足条件，所以是一片片、一条条的。Photography Life 那张织物照片就是左边一片彩色、右边一片波纹，别处没有（photographylife.com/what-is-moire）。
- 现在做的也是局部：只有鼓起处有条纹，每个部位最低的约 40% 一定没有。面积拉满时大约六成的丝袜面积有条纹（按条纹绝对值 > 0.1 算，五张测试图：b1-black 58.7%、b1-white 55.4%、b2-black 66.2%、b5-black 57.9%、sample 56.2%），其余是平处；面积调到 25% 时仍有 34%–56%，因为鼓得高的部位用一小部分高度也能出好几圈。
- 和现实的差别：现实里出现的位置不只是「鼓起的顶」，凡是两层的间距、方向、间隙变化的地方都会出（大腿两侧转弯处、褶皱、叠层的边、袜口和裆部加厚的地方），这里只按「鼓起」一种来画；现实里看不看得见还取决于相机分辨率和观看距离，这里不模拟。
- 没找到专门统计丝袜上摩尔纹出现位置的资料（搜索得到的综述是 AI 生成的，不当证据用），上面是从原理推出来的，不是对照实拍。

**怎么做**
- 条纹是深度模型鼓起图（`bulge`，视差单位，比原来的 `relief` 少了逐部位拉伸）的等高线，每圈 = 丝袜覆盖处整体深度跨度（视差 2%–98% 分位）的 4.5%（`MOIRE_STEP`）：鼓得越高环越多，平的地方（每个部位最低的约 40%）没有，部位大小不影响圈数，只决定圈有多大。实测拉满时顶处 3.8–7 圈。
- 鼓起图先在每个部位里各自模糊约 8 px（按图片大小缩放），再乘上面积（0–1），取 −sin(2π·h)，边缘用 tanh 压成清楚的条纹：用正弦不用余弦，平处不带条纹，亮暗条纹基本互相抵消。鼓起爬过 0.3–0.55 级之前不显示（`MOIRE_FIRST`），所以面积刚够时先出现一小块亮斑（顶上最亮、最受拉伸），不会为一点起伏就画条纹。
- 亮条纹处丝袜更亮、纹理对比更强，暗条纹处相反；亮度变化 13%（按「自动」强度，白丝按比例更小），纹理对比变化 90%。和纹理一样，近黑的地方、不在覆盖范围里的地方没有条纹。
- 整体亮度：面积拉满时变化在 ±0.9% 以内；中间值最多 ±2%，因为只出一两圈，像一块高光。
- 条纹比像素粗得多（拉满时有条纹处频率中位数 0.013–0.028 周/像素，每圈相隔约 36–77 px），自己不会混叠：对照 3 倍超采样，差异约 1%–4% 的信号，集中在部位边缘。局部更密的地方（鼓起变化太快，条纹比 0.06–0.14 周/像素更细）按纹理自己的办法淡出，占有条纹范围的 0.1%–4.7%。
- 叠在样式渲染之后、亮点之前，所以六种样式都能用，亮点不受影响。预览等于导出，细节方块和整体用同一张条纹图。
- 开销：深度算完后第一次约 0.14 s，每改一次面积约 0.05 s（只缓存最后一个面积的条纹图），改强度不用重算。
- 需要深度模型：它还没算完时画面先不带条纹，算完自动补上；不可用时导出图不带条纹，导出结果里会有一条提示。

**说法**
- 可以说：「想要摩尔纹时，有个试验开关，打开后有强度、面积两个滑杆；默认关；条纹顺着腿的鼓起走，从顶上一小圈往外扩，平的地方没有」「纹理本身不会出摩尔纹，这一点不变」。
- 不要说：「真实还原丝袜摩尔纹」。现实里的摩尔纹是两层织物或相机像素格的干涉，这里是按鼓起画的等高线条纹，看起来像，不是物理模拟。
- 还没试过的另一种：按「面向观众的程度」（油光样式的 `facing` 图）画条纹，条纹沿腿走，更像真丝袜，但细的地方更多（约 5–10% 被淡出），要再调。

代码：`look.py`（`bulge`、`relief_of`、`moire_phase`、`moire_fringes`、`moire_active`、`apply_moire`、`Scene.bulge_map`、`Scene.relief_map`、`Scene.moire_maps`、`Scene.moire_map(area)`、`MOIRE_*`）、`static/look.js`、`static/style.css`（`.switch`）、`server.py`（`_want_depth`、导出时等深度）

## 纹理页：预览和检查

**整体 Whole**
- 整张图渲染后缩到窗口大小，看整体观感。全图渲染约 0.5 秒，在滑杆停下后才更新。
- 中间有一条可拖动的分界线：左边是原图，右边是效果。
- 点一下整体图，细节就挪到那里。

**细节 Detail**
- 正方形，100% 或 200%（默认 200%），拖滑杆时实时更新：细线约 65 毫秒一帧，加濑风约 120 毫秒。
- 打开时自动对准横纹最密的地方，因为摩尔纹最先在那里出现。「回到最密处」可以跳回去。
- 拖动或用方向键看别处；按住空格看这一块的原图。

**预览等于导出**
- 细节里的像素和最终导出的同一位置完全一致，包括随机颗粒和亮点。
- 原因：所有随机场和需要全图信息的计算，都是对整张图做一次，预览只是从里面裁一块。

**标出问题 Show problems**：只在预览里显示，不会导出。
- 红色「减弱」：横纹间距接近像素大小，为了避免摩尔纹，纹理被减弱到一半以下。降低密度可以减少这一块。
- 蓝色「颜色排除」：被颜色排除去掉的地方。
- 黄色「没有走向线」：已经涂好但还没画走向线的部位。
- 每类都显示占已涂部位的百分比。

**怎么避免摩尔纹**（卖点，原理一句话版）
- 每一层条纹在局部频率接近像素能表达的极限之前就淡出（100% 密度时从 0.27 到 0.34 周/像素）。
- 线圈等小图案用多级预平均贴图采样，太密时平均成灰而不是混叠。
- 亮点是随机的单像素，不会混叠。
- 所以默认导出图的像素本身不含摩尔纹，100% 和 200% 看都没有圈纹。「摩尔纹效果」是另一回事：用户特意打开才有，条纹比像素粗得多，自己也不混叠（见上一节）。

## 安装和启动

**安装：** 双击 `install.bat`，安装界面全英文。五步：

1. **检测显卡：** 用 `nvidia-smi` 判断。Turing（RTX 20 系）及更新、驱动 ≥ 570 时用 CUDA 12.8 版 torch，否则用 CPU 版。可以用 `install.bat -Torch cpu|cuda` 强制指定。
2. **获取安装文件：** 先算出缺哪些文件，只拿缺的。
   - 来源依次是：
     1. **本地：** 文件夹里已有的安装文件包。
     2. **GitHub：** 本项目 GitHub Release [deps-1](https://github.com/silvermoong/stocking-texture-tool/releases/tag/deps-1) 上的安装文件包，这是默认来源。
     3. **原始来源：** GitHub 下载失败的文件，改从 PyPI、PyTorch、Hugging Face、Meta 等处下载。
   - 安装文件包：uv、Python 3.12.15、56 个依赖包、两个模型，每个文件都固定版本并校验 SHA-256。分 `base`（623 MB）、`torch-cpu`（113 MB）、`torch-cuda`（2.6 GB，按 GitHub 单文件 2 GB 的上限切成两块，安装时自动拼回）。
   - 显卡版共下载约 3.3 GB，CPU 版约 740 MB。
3. **建立 Python 3.12 环境（`.venv`）：** 用包里自带的 Python，不需要电脑上原本装有 Python，也不碰系统里已有的 Python。
4. **安装依赖包：** 全程不联网，只用拿到的文件。
5. **放好模型：** SAM ViT-B、Depth Anything V2 Small 放进 `models\`，然后在桌面建快捷方式「Stocking Texture Tool」（中文系统叫「丝袜纹理工具」），带程序图标。

**离线安装：** 在别处下载安装文件包（`base` 加一种 torch），原样放进 `install.bat` 旁边的 `deps` 文件夹，不用解压，也不要改文件名。双击 `install.bat`，全程不用联网。包里只有一种 torch 时，就装那一种。（安装程序也认放在 `install.bat` 旁边或上一层文件夹里的安装文件包，但说明里不写：Windows 自带的「全部解压缩」会多套一层同名文件夹，上一层就不是放安装文件包的下载文件夹了。）

- **重复运行安全：** 已经装好的部分直接跳过，缺的才下载，中途断网重新运行即可。更新显卡驱动后再运行一次，会从 CPU 版换成显卡版，只需下载 2 个文件。
- **全部装在项目文件夹里：** uv 和 Python 在 `.tools\`，模型在 `models\`。删掉文件夹和快捷方式就等于卸载。显卡版装完约 5 GB。
- **实测**（RTX 4090 这台机器，路径带空格和中文）：

  | 情况 | 用时 |
  | --- | --- |
  | 全新安装显卡版，从 GitHub 下载（约 54 MB/s） | 约 1.9 分钟（114.7 秒） |
  | 全新安装 CPU 版，从 GitHub 下载 | 约 1.6 分钟 |
  | 离线安装（显卡版，断网） | 约 40 秒 |
  | 已装好后重复运行 | 约 2 秒 |

  下载用时取决于网速；显卡版要下载约 3.3 GB。
- **启动：** 桌面快捷方式，或 `start.bat`；把图片或 PSD 拖到上面可以直接打开。
- **系统要求：** Windows 10（1803 及以上）或 Windows 11。安装时要能访问 GitHub，或者事先下好安装文件包离线安装。有 NVIDIA 显卡更快，但不是必须。
- **维护：** 只有改了依赖版本（`requirements*.txt`）才需要重新打包：`tools\make_deps.py deps-2`，上传到新的 Release，再提交 `tools/deps.json`。只改代码不用重新打包。

代码：`install.bat`、`tools/install.ps1`、`tools/deps.json`、`tools/make_deps.py`、`start.bat`、`requirements*.txt`、`tools/make_icon.py`（由一张方图生成 `icon.ico` 和 `icon-256.png`；`--tiled` 用于本身已经画成圆角方块的图）

## 准确的说法

| 用这个说法 | 原因 |
| --- | --- |
| 「沿横纹画几条线，横纹自动铺满并绕着身体走」 | 走向线只给方向 |
| 「横纹在屏幕上等距，间距由密度决定」 | 没有按深度变疏变密的功能（已删除） |
| 「体积感来自走向弧线、原画明暗、亮点位置、透肤和油光」 | 见「为什么看起来贴合身体」 |
| 「AI 用在点选和深度估算，纹理本身是算法生成的」 | 纹理是确定性的程序渲染，不是生成式 AI |
| 「油光是试验样式，适合有明显高光的纯色黑丝」 | 换图可能不稳定，界面上标了「试验」 |
| 「默认导出的像素本身不含摩尔纹」 | 别的看图软件缩小显示时，可能自己产生混叠；「摩尔纹效果」打开时，条纹是特意加上的，不是瑕疵 |
| 「Windows 本地运行，不上传」 | 安装后不联网也能用 |
| 「白丝的强度会自动调低」 | 实测白丝上同样纹理显得约两倍强 |

**白丝的状态：** 已用素材 B1 白丝实测：「自动」强度给出 40%（黑丝 100%），缝隙是粉色细线，效果正常。
